# 战斗架构：时序归代码，动画归表现，onHit 总线

战斗数值时序（前摇/判定帧/后摇/无敌帧窗口/取消窗口/预输入缓冲）全部放在 JS 状态机中，以 JSON 数据驱动、支持运行时热调；动画 clip 只做视觉呈现，通过与帧数据表的约定对齐（如 clip 前 X 秒对应前摇）。命中反馈经由单一 `onHit(info)` 事件总线，在同一帧扇出到六个通道（顿帧、受击白闪、特效、音效、镜头、手柄震动），每个招式携带一张手感档案（feel profile），反馈分五层级（普通/重击/削韧破绽/处决/识破）刻意拉开反差。

理由：打击感 = 同一帧上的多通道同步 × 反差与克制，而非特效堆料；调手感是本项目的核心迭代活动（本人为手感最终裁决者），必须做到"面板上拖滑块、立刻上手试"，而不是回 Blender 改动画再导出。

**Consequences**: 必须自建调校工作台（帧数据热调、判定可视化、慢动作逐帧、参数存档）——列为 M1 验收件；动画与帧表的约定对齐需要用 0.25 倍速逐帧检查工具保证；数值基准以拉片黑猴/只狼的实测帧数起步。
